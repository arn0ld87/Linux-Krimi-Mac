## Teil 2: native App, Core Loop (ca. 10 Minuten)
### Architektur
Swift Package (Swift 6, macOS >= 15/26 passend APIs) mit dependency-free reinem Foundation Library-Target `StaffelCore`, Executable `StaffelZwei` (SwiftUI + AppKit nur für Bridges) und XCTest/Swift Testing Target. Build-Scratch außerhalb T7 etwa `~/Library/Developer/StaffelZwei/build`. `build.sh` baut .app in `dist/StaffelZwei.app`; optional `--install` nach `~/Applications/StaffelZwei.app`, niemals vorhandene App ungeprüft überschreiben. Ad-hoc codesign, kein Zertifikat nötig. Bundle-ID wie oben. Kein Auto-Commit. Build zunächst vor Features oder frühestmöglich zum Toolchain-Nachweis.

### M1 bewusst begrenzt
**Spielbar nur Episode 0 Probelauf**. Episoden 1–3 übersichtlich als „Später verfügbar“ mit echten Titeln aus Quelle (keine vorgetäuschte Play-Funktion). **Kein echtes Linux in M1**: gut sichtbarer Text „Lokale Übungssimulation – keine Befehle auf deinem Mac“. Kein Process/shell für Eingaben, keine echten Dateizugriffe aus Terminal, keine Netzwerkverbindung im App-Betrieb. Nicht so tun als sei Simulator eine VM. Nicht nur eine Folge hartcodierter freischaltender Buttonklicks: kleine dateibasierte Shell-Simulation mit Parser und deterministischer In-Memory-Dateiwelt.

Eine hochwertige, benutzbare Mac-Oberfläche statt generischem Template: NavigationSplitView Sidebar mit Fall und Seiten, oben Episode/Titel, mittig Akte/Spuren mit gut lesbaren Schritten, daneben Terminal (oder eigene Seite bei wenig Platz), Aktenwand mit echten gesicherten Ausgaben, Vorwurf-Sheet oder eigene Ansicht.
